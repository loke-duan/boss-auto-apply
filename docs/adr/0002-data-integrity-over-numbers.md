# 数据诚信优先于「有数值」

简历中的量化数据，**可信、可验证、有基数参照** 三者必须同时满足，否则不得保留。禁止为「让简历显得有数据」而保留站不住脚的数值，也禁止凭经验编造「不夸张的数值」。

## 背景

用户原诉求：「HRBP 方案没有数值显得空洞，要用可量化数值打动 HR」。但简历常见数值存在：转化率缺基数、增长倍数基数不明、排名体量无参照、绝对值过小反向暴露等问题。

## 决策

数值保留的三条规则（F1.6 体检 + F4 定制共同遵守）：

1. **可信**：求职者能说清楚来源（怎么算的、基数多少）
2. **可验证**：背调/社保/个税/前同事可佐证
3. **有基数参照**：单独的百分比/倍数必须配基数，否则用绝对值+结果替代

**不满足时**的降级方案（按优先级）：
- 用「稳定增长」替代「无基数的倍数」（流量翻 N 倍 → 自然搜索流量稳定增长）
- 用「持续上升」替代「无参照的排名」（排名第一 → 核心关键词排名持续上升）
- 用「显著提升」替代「缺基数的百分比」（转化率 X% → 注册转化率显著提升）
- 用「过程价值」替代「小体量绝对值」（少量线索 → 协同销售搭建线索流转闭环）

## 后果

- 简历看起来「数值变少」，但每个数值都站得住脚，面试可答
- 这是与求职者「想要更多数值」直觉的对抗点，需 HRBP agent 强制执行
- 如果求职者后续提供了真实可信的新数值，可补充进 master.json
